# CLI 命令

无参数时保持原有 HTTP 启动流程；收到 Ctrl-C 或 SIGTERM 后优雅关闭。
`--help` 在读取配置前输出帮助，未知参数或多个模式返回非零且不创建日志、数据库或监听端口。

## 初始化数据库

```bash
cargo run --release -- --init-db
```

该模式读取相同的 `.env`、进程环境和默认值。它仍要求完整 `AppConfig` 合法，包括 JWT 配置，
且 `APP_ENV=production` 必须搭配 release 构建；但不会构建 JWT 服务、业务容器、日志文件或 HTTP 服务。

初始化复用普通启动的 SQLite 连接与迁移流程：

1. 先拒绝已知内存 URL，再连接持久 SQLite 数据库；实际主数据库没有文件时同样拒绝，内存库不能作为部署产物。
2. 执行 SQLx 迁移、老库 `request_id` 补列与索引创建。
3. 幂等创建缺失的演示账户，已有账户的余额、版本、流水与审计不变。
4. 关闭数据库连接池，全部成功才向标准输出写入完成信息并退出 0。

端口被占用不影响命令。连接、迁移、补列、索引、播种或关闭失败时向标准错误报告阶段并返回非零，
不回显数据库 URL 或密钥，不输出成功消息。初始化会修改数据库，并不是覆盖整个过程的单一事务，
失败时部分迁移可能已经生效；修复失败原因后可再次执行。无参数启动仍保留自动初始化行为。

内存数据库判定先解析 SQLite 连接选项，覆盖普通 `:memory:`、`mode=memory`、URI 和编码后的内存名称；
连接后继续用 `pragma_database_list` 确认实际主库有文件，避免把临时数据库误报为持久化部署产物。

## 静态配置预检

```bash
cargo run --release -- --check-config
```

命令使用与正常启动相同的 dotenv 加载顺序：进程环境优先于 `.env`，缺省值由 `AppConfig` 提供。
预检复用正常启动的配置解析、production 构建守卫、日志时区/过滤器及 SQLite 共享缓存校验。
不初始化日志订阅者、连接数据库、迁移、播种、构建业务容器或监听 HTTP；既有文件也不会改写。
共享内存库可通过静态检查，`--init-db` 的持久化要求只用于数据库初始化模式。
内存池使用 `sqlite::memory:`，或命名的 `sqlite:file:pool-name?mode=memory&cache=shared`。
`cache=private`、编码后的裸 `:memory:`、空名称或普通文件名称加 `mode=memory` 不能保证池中
多条连接访问同一数据库，因此在静态检查与正常连接前拒绝；缓存选项按 SQLx 的参数顺序生效。

成功时标准输出说明静态检查范围并退出 0；错误时标准错误指出配置项或约束并非零退出，
不输出 JWT 密钥、数据库 URL 或完整配置。命令不检查数据库连通性、文件权限及端口占用；
配置语法合法但数据库不存在、日志路径不可写或端口被占用时仍可以通过。
检查后配置或环境发生变化也不在本次结果保证范围内。

`--check-config`、`--init-db`、`--export-openapi` 与 `--help` 互斥，混用在读取配置和资源初始化前失败。
无参数仍启动服务，并使用同一静态校验入口；非法日志或私有内存缓存配置会在创建任何运行资源前失败。

## 离线导出 OpenAPI

```bash
cargo run --quiet --release --features docs -- --export-openapi > openapi.json
```

该模式在 dotenv 加载、配置解析和资源初始化之前执行；缺少 JWT 配置、数据库不可用或端口已占用
均不影响导出。命令复用 HTTP `/api-doc/openapi.json` 的同一文档构造入口，不维护第二份接口或 schema。
标准输出只写入一个可解析的 JSON 文档，不混入日志或完成提示；输出由调用方重定向保存，命令不主动创建文件。

默认 feature 仍不包含 `docs`。未启用时命令向标准错误说明 `requires the docs feature` 并非零退出，
不会继续启动服务。序列化、标准输出写入或 flush 失败同样非零退出；写入失败时已输出的部分数据
不能视为完整文档，自动化任务必须检查退出状态。

文档内容反映编译模式：debug + docs 包含 dev-login / dev-transfer 路径，release + docs 裁剪这些路径。
切换 `APP_ENV` 不改变已编译的文档；推荐发布文档时使用 release + docs。
导出成功只证明当前声明能够生成并输出，不代表接口契约已全面验证或兼容所有下游工具。

## 验证

`tests/cli_tests.rs` 使用独立进程、临时目录和真实 SQLite 文件，验证新库、历史库、重复执行、
唯一索引、故障退出、不监听 HTTP、静态预检的无副作用与配置来源，以及普通服务的启动和信号关闭。
测试不会读取本地 `.env`。
`tests/database_tests.rs` 通过同时持有两条真实连接验证受支持内存库的迁移和演示数据可见性。
导出测试使用独立进程，验证无配置依赖、纯 JSON、与 HTTP 文档一致、feature 提示、模式冲突及输出失败；
四种构建组合的检查命令见 [测试与构建检查](TESTING.md)。
